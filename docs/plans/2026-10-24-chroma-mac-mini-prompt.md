# 새 Mac mini의 리니베라·Chroma 작업 이어가기

리니베라의 Chroma Awards 조사와 구현을 이 Mac에서 이어받아 작업 준비를 완료해줘.

저장소: https://github.com/fbwndrud/linivera
인수인계 브랜치: codex/chroma-research-handoff-2026-10-24
진입 문서: docs/plans/2026-10-24-chroma-research-handoff.md

## 진행 순서

1. 현재 작업 위치와 변경 상태를 확인한다. 아직 clone하지 않았다면 적합한 새 폴더에
   위 브랜치를 clone한다. 이미 작업 중인 폴더의 파일과 변경은 보존한다.
2. AGENTS.md와 진입 문서를 읽고 체크섬을 검증한다. 실제 clone 경로를 기준으로 작업한다.
3. 최신 사용 안내, PR #9 최종 리뷰 대조, 필요한 조사 원문을 읽는다. 날짜가 지난 계획의
   미병합 상태나 테스트 수치를 현재 상태로 사용하지 말고 최신 Git/코드와 구별한다.
4. package.json의 지원 Node를 확인하고, npm run setup으로 소스 실행 환경을 준비한다.
   기존 Mac의 사용자 이름·캐시 런타임 경로는 복사해서 쓰지 않는다.
5. node examples/chroma-continuity.js를 실행하여 같은 작업 공간의
   입력 명세→보유 자료 대조→연결 준비→맥락 묶음→요청→합성 공식 도구→결과 보관→
   P0~P4→후속 두 작업을 검증한다. 설치/경로/환경 문제는 원인을 확인해 해결한다.
6. 현재 호스트에서 리니베라 MCP가 필요하면 docs/connect.md를 따라 source 실행 경로와
   실제 노출 도구를 확인한다. 공급자 인증과 계정·권한·크레딧은 별도로 확인한다.
7. 새 Mac에서 재현한 결과, 읽은 자료, 현재 지원 범위와 남은 확인 사항을 보고한다.
   이후 내가 지정하는 작업은 별도 codex/ 브랜치에서 계획·구현·검증한다.

## 보존할 목표와 경계

리니베라는 생성 모델 자체보다 자료·정확한 판본·맥락·증거를 연결하여 다음 반복 작업에
쓸 수 있게 하는 MCP다. 입력/출력 명세와 보유 자료 대조, 계정 연결 준비, 맥락 묶음,
Resource→Input→Operation→Review의 관계를 유지한다.

37개 파트너 조사표와 실행 가능한 대표 명세를 구분한다. 공식 MCP/스킬이 충분하면 재사용한다.
가입·인증·유료 호출·크레딧 적용·실제 미디어 복원을 합성 테스트 결과로 간주하지 않는다.
필요한 실제 계정 단계는 사용자에게 안내하고 자격 증명은 호스트 secret 관리에 둔다.
기존 카탈로그 ID/hash와 과거 Input을 보존하며 새 명세는 새 판본으로 추가한다.

합성 fixture만 커밋하고 실제 작품·생성 결과물·비밀값은 보관 코드 저장소에 올리지 않는다.
core의 모델/네트워크 금지와 잠금 규칙을 유지한다. 소통은 한국어로 한다.
이 브랜치는 코드·문서 인수인계이며 기존 Mac의 미커밋 작업·작품·인증·채팅 이전은 포함하지 않는다.
