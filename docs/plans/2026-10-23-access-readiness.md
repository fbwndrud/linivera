# 입력과 연결·계정 준비 상태를 함께 검증

추가 승인 범위. 기준은 PR #9 head `4e13617`; 같은 브랜치/작업 트리/PR을 유지한다.
기존 #8 의존, 주 작업 디렉터리/원래 점검 트리 변경 보존, 합성 fixture 원칙도 유지한다.

## 설계

기능 명세·자료 대조·맥락 묶음·Input·v2 Operation은 재사용한다. 확장은 접근 경로별 버전
명세, 비밀값을 받지 않는 연결 점검 기록, 입력 대조와 나란한 공개 연결 대조, 공식 도구의
결과를 기존 recorder로 보관하는 호스트 절차다. core는 네트워크/모델을 호출하지 않는다.

- 접근 identity는 파트너/기능/모델/endpoint뿐 아니라 API·웹·CLI·공식 외부 MCP·제품 내부
  MCP 수신·공식 스킬·수동 export를 구분한다. 공식/커뮤니티·기능 불일치를 표시한다.
- 버전 명세에 가입/인증 방식/권한/요금제/크레딧과 Chroma 적용 경로·활성화·기한의
  확인 범위를 기록한다. 근거 없는 일반화나 미확인 경로의 부재 단정은 하지 않는다.
- 연결 증거는 구조화된 allowlist의 enum/boolean/숫자/시간/정확 판본·비밀이 아닌 로컬
  계정/프로젝트 별칭만 받는다. token/cookie/header/URL query/인증 원문을 보관하지 않는다.
  호스트는 기존 secret 관리로 인증하며 raw 도구 응답도 Resource/로그에 직접 넣지 않는다.
- 설치/호스트 노출, 인증, 기능 권한, plan, balance/credits를 독립 상태로 다룬다. 하나라도
  차단·미확인·부분·만료면 준비 완료가 아니다. account/project/route/time 근거를 고정한다.
- 저장 보고는 과거 점검 사실이다. 새 실행 직전의 신선한 점검과 정확한 요청·접근 identity를
  다시 확인하며 기존 정책/승인 잠금은 별도다. 과거 Input/hash 검증은 현재 clock에 의존하지 않는다.
- 충분한 공식 MCP/스킬/CLI는 재사용한다. 대표 Meshy MCP의 schema/tools 확인·잔액 조회·
  생성·상태·download 절차를 호스트 callback으로 주입하여 실행기를 중복 구현하지 않는다.
  실제 공급자 도구를 호출하지 않고 합성 도구 fixture만 사용한다.
- 공식 도구 성공과 파일 확보·Linivera 보관을 별도로 기록한다. signed URL만 관측했다면
  보관 완료가 아니다. 부분 다운로드·재시도 시 기존 실행·결과를 이어 쓰고 생성은 재호출하지 않는다.

## 순서와 수용 기준

1. 전체 37개 파트너의 접근 현황과 대표 공식 경로의 상세 근거를 조사한다.
2. 접근 명세/점검 allowlist/연결 대조와 공개 MCP 보관·검증을 구현한다.
3. 입력 대조와 함께 필수 맥락 역할로 고정한다. 관련 변경·만료·요청 바꿔치기를 새 작업에서 차단한다.
4. 공통 공식 도구 호스트 경로와 합성 fixture를 단일 P0~P4 예제에 연결한다.
5. 미설치/미노출/미인증/권한·plan 부족/credits 미확인·부족/만료·부분 점검을 검사한다.
6. 부분 결과·다운로드 실패·재시도·URL-only·비밀값 비기록, 원본 삭제·재시작 후 실제 bytes,
   정확한 계정/프로젝트/요청 결속·scope/예산·역사 Input과 기존 잠금 회귀를 검사한다.
7. lint/typecheck/전체 check와 dev dependency 없는 tarball을 다시 실행한다.
8. code-review Standards/Spec 독립 병렬 검토·지적 수정·회귀·재검토 후 PR #9 설명을 갱신한다.

가입/결제/구독/유료 생성/외부 게시/실계정 인증·공식 MCP 실호출은 수행하지 않는다.
사람의 단계는 공식 안내와 다음 조치로 반환한다. 실제 외부 검증 경계는 결과와 문서에 명시한다.
