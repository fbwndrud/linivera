# 원고·검토·출판 화면 사용하기

Linivera를 책상이라고 생각하면 쉽다. **Manuscript**는 원고를 펼치는 곳,
**Review**는 기록과 근거를 비교하는 곳, **Publish**는 읽을 파일을 받는 곳이다.
AI에게 “이 작품의 Linivera 화면을 열어 줘”라고 요청한 뒤 상단 메뉴를 사용한다.

## 1. 원고를 읽다가 설정을 확인하기

**Manuscript**에서 목차의 절을 선택한다. 목차가 숨겨져 있으면 **Show contents**를 누른다.
**Reading settings**로 글자 크기와 줄 간격을 바꾼다. **Focus mode**에서는 원고에 집중한다.

**Show details → Tracking**에서 따라볼 대상을 고른다.
**Latest recorded**는 현재 절까지 기록된 값을, **Changes**는 변화 기록을 보여 준다.
뒤에 나올 절의 정보는 섞지 않는다. 서로 다른 사람의 생각·경로·작품 내 시점은 따로 남긴다.
분기처럼 하나의 순서를 정할 수 없으면 현재 상태를 추측하지 않고 Review에서 비교하도록 안내한다.

기록의 **Show in manuscript**를 누르면 근거가 있는 절로 이동하고 문장을 강조한다.
원고가 수정되어 본문 버전이 다르면 오래된 문장을 현재 근거처럼 강조하지 않는다.
**Section review**에서 기존 검토 지적과 자기검토 여부도 확인한다.

## 2. 기록을 원문과 비교하기

**Review → Evidence desk**에서 **Subject**, **Criterion**, **Group**을 고른다.
표의 절 제목을 누르면 오른쪽에 그 기록의 인용과 실제 원문이 나온다.

- **Stated in text**: 원문에 명시된 내용으로 제출된 기록.
- **Attributed belief**: 특정 인물이나 사람의 생각으로 제출된 기록.
- **Inference**: 추론으로 제출된 기록.

이 표시는 AI가 제출한 구분을 보존한다. 엔진이 의미의 진실을 보증하는 표시는 아니다.
**Source version**에서 본문 버전과 검토 기록을 확인한다.
아래 연결 화면은 선택한 대상이 언급된 절의 목록이다. 언급만으로 인물 관계를 만들어 내지 않는다.

원고·기준이 바뀌면 이전 관측이 활성 목록에서 빠질 수 있다. 빈 목록을 “변화 없음”으로 읽지 않는다.
coverage는 기록된 범위의 검사 상태이며 의미 정확도 점수가 아니다.
기록이 없는 절, 다시 검토할 범위, 같은 AI의 자기검토를 따로 확인한다.
**Review records**와 **Check groups**에서 기존 검토 화면을 계속 사용할 수 있다.

## 3. 변경한 뒤 어디를 다시 확인할지 보기

**Review → Changes**를 연다. 원고·설정·이미지·자료·추적 규칙 변경으로
기존 검토에서 참고한 버전이 달라진 구간을 보여 준다.

1. **Change type**이나 검색으로 바뀐 항목을 찾는다.
2. 카드의 항목 링크로 현재 원고·설정·자료를 확인한다.
3. **Before and current versions**에서 당시 값과 현재 값을 비교한다.
4. **Open section review**로 지적과 기록을 확인한 뒤 AI에게 해당 구간 재검토를 요청한다.
5. 재검토 결과를 확인하고 **Refresh view**를 누른다. 수정 원고라면 다시 작성/커밋하는 절차가 필요할 수 있다.

비어 있는 목록을 “작품 전체가 일관됨”으로 해석하지 않는다. **Sections without a finalized review**는
아직 확정 검토가 없는 원고 구간 수이고, **Tracking checks still pending**은 구간×기준별 미완료 검사 수다.
이는 같은 단위가 아니다. 영향을 받는 상위 그룹도 section 카드에 나타날 수 있다.
서로 다른 판본 상태와 Resource 검색의 최신성은 따로 표시한다.
검증할 수 없는 활동 기록/설정은 변경 정보 unavailable로, 근거 연결 검사 꺼짐/손상은 별도 안내로 표시한다.

이 화면은 기록된 의존성을 확인한다. 모든 의미적 영향이나 누락된 연결을 자동 발견하지는 않는다.
원고를 조용히 고치거나 작가 승인을 대신하지 않는다. 이미 받은 책 파일은 과거 사본이므로
검토가 끝나면 **Publish**에서 새 파일을 받는다. 새 정적 검토 사본에도 Changes가 포함되며
사본에 담긴 시점의 상태를 보여 준다. 이전 사본은 정보 미포함 안내를 제공한다.

## 4. 읽을 파일 받기

**Publish**에서 계층형 목차를 선택해 저장된 원고를 미리 본다.
미리보기는 연속 본문이며 자동 조판이나 종이 페이지 수를 계산하지 않는다.

- **Web book ZIP**: 페이지·스타일·그림과 manifest를 내려받는다. 압축을 풀고 index.html을 연다.
- **EPUB**: 전자책 파일을 내려받는다. 부모 그룹 제목과 본문 절의 목차를 보존한다.
- **Export review view**: 본문과 검토 기록을 함께 볼 읽기 전용 화면 사본을 만든다.

화면 다운로드는 상단 **읽는 판본 / Reading edition**에서 고른 판본을 사용한다.
판본을 고르지 않으면 **main**이며, UI 언어 선택은 출판 언어를 바꾸지 않는다.
출판 언어를 명시적으로 바꾸려면 AI에게 `folio_export`의 `language` 인자로 요청한다.
그룹의 계획 메모는 책 본문에 섞지 않는다. PDF는 Web 페이지의 브라우저 인쇄를 사용한다.
미확정·수정 원고도 내보낼 수 있으므로 export 경고와 검토 기록을 확인한다.
내보내기는 작가 승인이나 온라인 게시를 대신하지 않는다.

## 공유한 사본에서 볼 수 있는 것

새 검토 사본에는 세 모드의 읽기 정보가 포함된다. 원고·설정·검토·추적을 볼 수 있지만
새 책 다운로드와 쓰기 기능은 제공하지 않는다. 원본 작업 화면에서 다시 내보낸다.
이전 사본에는 추적·출판 정보가 없을 수 있다. 미포함 안내를 확인하고 새 사본을 요청한다.

## Library와 Story threads에서 데이터 읽기

**Story threads**는 **Recorded developments**에서 도입·전개·해소 기록을 읽는다.
**Section timeline**을 열면 구간별 사건을 비교할 수 있다. 긴 제목은 줄바꿈하고 옆으로
스크롤하며, 상위 그룹에 기록된 사건은 목록의 **Group note**에 남긴다. 그룹 사건을 첫
본문 구간의 사건으로 옮겨 표시하지 않는다. 마지막 확정 구간과 마지막 작성 구간은 구분한다.

**Figures & references**에서 그림·교차 참조·각주·인용 자료·이름 색인을 탭으로 나눠 본다.
색인은 이름을 검색한 뒤 항목을 펼쳐 사용 구간을 확인한다. 없는 자료와 깨진 참조는
원문 구간·줄 번호로 확인하며, 실제 이미지 파일은 원고와 출판 미리보기에서 본다.
그림 탭은 원고의 그림·표 등 참조 대상을 보여 준다.

**Connections**는 정의 하나를 선택해 실제 언급과 선언된 연결을 먼저 목록으로 보여 준다.
**Show diagram for these references**는 같은 목록을 시각화한다. 좁은 화면에서는 세로로
배치하고 큰 도표는 이동해서 탐색한다. 언급 횟수만으로 의미적 관계를 추론하지 않는다.

리소스·사건·정의의 중첩 데이터는 이름과 값으로 읽는다. 사용자 정의 필드는 보존하며
시스템 필드와 같은 이름이라고 시스템 의미로 바꾸지 않는다. 0, false, null, 빈 배열과
빈 문자열도 표시한다. 버전 식별자와 fingerprint는 접힌 상세에서 확인한다.
완전한 JSON 자료는 항목별로 보여 주고, 잘렸거나 잘못된 JSON은 원본을 보존한
**Original source text**에서 확인한다. 화면에서 승인 기록이나 원고를 자동 수정하지 않는다.

**Check groups**의 카드에서 선택 여부, 기본 추천, 추천 이유와 검사 영향도를 확인한다.
**Always required** 검사는 그룹 선택과 관계없이 유지된다. **Versions used**의 탐색 링크는
현재 이름을 사용하며, 당시의 정확한 버전은 **Content fingerprints**로 구분한다.

화면 상단의 **언어 / Language**에서 **한국어 / English**를 고를 수 있다. 선택은 브라우저에 저장되며 새로고침 후에도 유지된다. 처음에는 지원되는 브라우저 언어를 사용하고 없으면 영어를 사용한다. 내보낸 검토 사본도 선택을 지원한다. 언어는 UI 안내만 바꾸며 원고·제목·인용·사용자 규칙은 원래 언어를 유지한다.


## 원본과 번역본 읽기

현재 소스를 빌드하거나 새 판본 지원 예시를 열면, 판본이 선언된 작품의 상단에 **읽는 판본 / Reading edition**이 나타난다. 원본·번역·개정·요약 가운데 선언된 판본을 고른다. 이 선택은 UI의 **한국어 / English** 선택과 별개다.

본문, 구간 검토 기록, 출판 미리보기와 살아 있는 화면의 Web/EPUB 다운로드가 같은 판본을 사용한다. 검토 기록에서 번역이 근거로 삼은 원본 버전을 확인할 수 있다. 목차·설정·자료·추적·작품 전체 검토 요약은 원본 기준이며 화면 안내로 구분한다. 선택이나 조회만으로 승인·수정 기록을 만들지 않는다.

번역이 빠진 구간은 미작성으로 표시하고 원문을 대신 넣지 않는다. 모든 구간의 번역이 없으면 그 판본의 책 다운로드를 거부한다. 원문·용어표·번역 본문이 검토 뒤에 바뀌면 다시 검토할 상태를 알린다. 손상된 기록장에서는 검토 성공을 추정하지 않는다.

새 읽기 전용 Studio 사본에는 판본별 본문과 영수증 및 번역에서만 사용한 그림도 포함한다. 정적 사본은 새 책 다운로드를 만들지 않으므로 살아 있는 작품에서 내보내거나 묶음에 포함된 Web/EPUB를 연다. 이전 사본·최초 0.1.0 엔진 묶음에는 판본 선택기가 없고 원본 조회를 유지한다.

## 제작 데이터와 Resources

**Library → Resources**에서 선택한 원본과 승인 결과의 정확한 판본·근거·자기검토·
재검토 필요 상태를 읽는다. 후보 파일 반입만으로 이 목록의 승인 결과가 되지는 않는다.
목록이 **Not indexed**이거나 오래됐으면 호스트에게 metadata 갱신을 요청한다.
생성 파일의 binary 원본은 정적 검토 사본에 넣지 않는다. 원본 보관과 백업은 별도로 유지한다.

0.1.3의 파일/묶음·후보별 검토·입력/연결 준비·맥락 묶음·후속 제작은
[문서 안내](README.md)의 순서를 따른다. 화면 조회만으로 선택·검토·승인 기록을 만들지 않는다.
