# 지원 환경과 한계

## 실행 환경

Node.js 범위는 `^22.13.0 || ^24.0.0 || ^26.0.0`이다. Node 24를 권장한다.
내장 `node:sqlite`를 사용하므로 Node 20·23은 지원 범위가 아니다.
설치에는 npm과 레지스트리 접근이 필요하지만 엔진 실행은 네트워크를 호출하지 않는다.
호스트의 모델 연결과 비용은 호스트 설정에 따른다.

GitHub Actions CI는 사용하지 않는다. Node 지원 범위가 모든 OS·Node 조합의
검증 완료를 뜻하지는 않는다. 실제 로컬 실행 범위는 [검증 기록](testing.md)을 확인한다.

stdio MCP 호스트가 필요하다. 자동 테스트는 Node MCP SDK 클라이언트로 실행 파일에 연결한다.
실제 호스트 UI와 모델의 답변 정확도를 이 테스트가 보장하지는 않는다.

## 구현된 범위

- 소설 프리셋: 연재(arc → episode), 장편(book → chapter → scene), 단일 장면.
- 그림책 원고(book → spread)와 동화(chapter → scene) 프리셋. 그림책의 읽을 글·그림 설명을 나눠 저장한다.
- 호스트 스킬에 쉬운 설명(ELI5) 지침. 실제 UI나 그림 생성 기능은 아니다.
- 지식 책 프리셋: 교재(part → chapter → section), 역사(era → chapter → section), 안내서.
- 자료 책: 로컬 자료 넣기·읽기·주장 인용 연결과 근거 검사.
- 순서대로 실행, 영수증, 사건 기록, 엔티티 사용처, 재검사, 이름 바꾸기와 다시 커밋.
- 설정·팩으로 해제할 수 없는 잠금과 같은 호스트의 자기검토 표기.
- 공통 자산 도구: 설명서·파일/URI 인계·버전·연결·검토 영수증·작가 승인/수정 요청.
  파일 바이트 hash를 확인하며 생성·시각 검토는 호스트가 수행한다. URI만으로 승인하지 않는다.
- 로컬 뷰어와 Resources 목록·상세, 정적 검토 사본. 소스는 setup으로 화면을 빌드하고 준비된 tarball은 화면을 포함한다.
- 웹·EPUB 내보내기와 수동 지면 좌표 배치, 판본별 집필·검사, 호스트가 생성하는 별도 그림 실행.
- 게임북 분기 구조 검사와 선택지 링크. 의미적 연속성의 모델 검토에는 품질 한계가 있다.
- Resource 전용 폴더의 선택 원본·승인 결과 metadata 조회. 선택 embedding은 별도 오프라인 런타임을 사용한다.
- 원고·Resource 폴더의 읽기 전용 `linivera-doctor` 진단과 새 사본의 백업 복원 확인.
- 0.1.3 소스: 최대 2GiB 단일 파일의 스트림 보관, 4096개 멤버·8GiB 이내 묶음과 실행/후보별 영수증.
- 회차별 정확 판본 선택, 반복 의도·사용 맥락·필수 역할 묶음과 두 단계 후속 작업의 변경 재검토.
- workflow/3D/자막·편집·프로젝트/atlas·DB 증거·응답/권리/배포 데이터의 명시적 구조 연결.
- 대표 기능 4개·접근 6개 명세, 입력/연결 준비 대조와 구판 카탈로그 보존. 37개 파트너 조사와 실행 지원은 구분한다.
- 호스트가 주입한 fal·ElevenLabs·Meshy transport, 공식 Meshy MCP의 명시된 지원 교집합 재사용.
- 선택 이미지/음원을 샷·타임라인·영상으로 잇는 로컬 FFmpeg 모션 경로. FFmpeg는 별도 설치가 필요하다.

설치 패키지는 현재 공개 0.1.2와 준비 중인 0.1.3을 구분한다. 위 새 제작 경로와 형식별 한계는
[문서 안내](README.md)와 [지원표](chroma-support.md)를 따른다. 일반 파일의 2GiB 보관 한도가
기존 인라인·모션·Vector 입력의 더 작은 예산을 확대하지는 않는다.

## 아직 제공하지 않는 범위

- 설치 없는 웹 서비스·클라우드 작품 저장과 전체 작품 목록 화면.
- 엔진의 직접 PDF 생성, 자동 조판, 모든 전자책 리더의 동일한 지면 재현. PDF는 브라우저 인쇄를 쓴다.
- 모든 분기 경로에서의 의미적 연속성·게임 균형을 보증하는 검사. 구조 검사 통과가 완성된 게임북 품질을 보증하지 않는다.
- vibelore 검사기 전체 이식. 현재 소설 팩은 제한된 기본 검사만 제공한다.
- 자동 손상 복구와 여러 프로세스의 임의 기록장 직접 쓰기.
- 37개 파트너 전체 실행기, 자동 계정 생성/결제, 실제 공급자 설치·가용성·권한의 합성 테스트 인증.
- 프로젝트를 원래 편집기/엔진에 자동 복원하거나 모든 미디어의 재생·품질·권리 유효성을 보증하는 기능.
- 외부 자동 게시·성과 진실성 인증. 공급자 관측은 `host-reported`이며 공식 도구 성공도 보관·승인을 대신하지 않는다.

실험적 비문학 검사는 기본 advisory다. 숫자 대조에는 `㎡`·위 첨자 정규화와
`1.50`/`1.5` 비교 등의 알려진 한계가 있다. 현재 결정론 검사는 결과 지적의
severity를 선언보다 높일 수 있다(로드맵 S에서 제한 예정).
외부 JS 팩은 신뢰하는 코드만 등록한다. 팩 실행은 샌드박스가 아니다.

팩 보조 코드의 변경은 digest로 감지한다. JS 팩의 숨은 클로저와 팩 밖 입력은
[팩 작성 규칙](packs.md)에 따라 명시해야 한다.
모델이 근거 있는 주장이나 사건을 누락하는 경우까지 결정론 검사만으로 판별할 수는 없다.

## 파일 접근 범위

서버는 작품 `root`가 절대 경로인지 확인하지만 허용 폴더 목록을 두지 않는다.
호스트에는 작가가 고른 작품 폴더만 전달한다.
자료·자산의 `path`는 호스트가 전달한 로컬 파일 하나를 읽는 기능이다.
한 작품의 쓰기는 도구를 통해 수행하며 기록장을 직접 수정하지 않는다.
작품은 로컬 폴더이고 백업은 별도로 관리한다.

## Folio 이름을 쓰던 설치본

제품 표시명은 Linivera(리니베라), 새 패키지는 `linivera`다. 기존 작품은 변환 없이 열고 `work.yaml`·`.folio`·원고·승인 영수증을 유지한다. MCP 도구 ID `folio_*`, 기존 `folio-*` 명령, `skill/folio/` 및 `FOLIO_EMBEDDING_*` 설정은 호환용으로 보존한다. 새 설치의 MCP 스크립트 경로는 `node_modules/linivera/bin/linivera-mcp.js`다. 기존 설치본과 정적 사본은 재연결/재내보내기 전까지 이전 이름을 표시한다. [업데이트 순서](production.md#기존-설치-갱신과-롤백)를 따른다.
